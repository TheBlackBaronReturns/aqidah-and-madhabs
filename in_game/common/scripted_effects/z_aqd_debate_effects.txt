# ---------------------------------------------------------------------
# aqd_debate_pick_pair: picks a PIVOT eligible seat (uniformly among
# owned locations via the umbrella aqd_debate_seat_eligible OR, then a
# reservoir-sampled madhhab among however many that location actually
# has eligible - identical idiom to scripted_effects/z_aqd_jihad_fatwa_
# effects.txt's aqd_jihad_fatwa_pick_seat, see that file's own header for
# the full Algorithm-R reasoning), then a PARTNER seat drawn from the
# pivot's own AREA.
#
# The partner draw is two steps, not one, because EU5's random_list only
# takes literal integer weights (script_values/z_aqd_madhhab_approval.txt's
# own header notes this constraint) - fine for a fixed set of 9 madhhabs
# at one location, but an area can hold an open-ended number of owned
# locations, so there is no way to hardcode reservoir-promotion odds for
# "the Nth eligible location in this area" the way the existing pickers
# do for "the Nth eligible madhhab at this location". Base game's own
# random_location_in_area (confirmed usage: events/institution_events.txt)
# already does a uniform pick over locations in an area scope, so step
# one reuses THAT for the location, and step two re-runs the same
# fixed-9 Algorithm-R idiom used elsewhere in this mod to pick which
# madhhab at whichever location won.
#
# scope:debate_area is captured via area = { save_scope_as = ... } at the
# pivot's own location scope - the confirmed "location -> area scope"
# transition idiom (events/religion/z_aqd_fatwa_events.txt's z_aqd_
# fatwa.2 already does exactly this: area = { save_scope_as = target_area }
# from inside its own random_owned_location block).
#
# The partner draw's own random_location_in_area limit is deliberately
# the CHEAP umbrella check (aqd_debate_seat_eligible = yes, "does this
# location have ANY eligible seat"), not a smarter "has an eligible seat
# OTHER than the pivot's own madhhab" check - the pivot's own location
# always trivially satisfies the cheap check too, so it can legitimately
# be drawn as its own "partner location" candidate. That is fine: the
# second reservoir pass below (at scope:debate_location_b) is what
# actually excludes the exact (pivot location, pivot madhhab) PAIR - it
# still allows a DIFFERENT eligible madhhab at that same location. If the
# draw lands on the pivot's own location and that location turns out to
# hold no OTHER eligible madhhab, the second pass simply finds nothing
# and var:aqd_debate_seat_b_madhhab is left unset - the attempt aborts
# silently (aqd_debate_attempt below) and tries again next pulse, same
# "good enough, retry later" tolerance this mod's other silent-miss
# systems already rely on rather than guaranteeing perfect uniformity.
# ---------------------------------------------------------------------

# ---------------------------------------------------------------------
# aqd_debate_attempt: country-scoped, called from the pulse's effect
# (on_action/00_aqd_game_start.txt's aqd_debate_pulse), NOT from an
# event - same silent-miss shape as every other fatwa pulse in this mod:
# the full pick happens here, before any popup exists, so a failed pick
# (no valid area-mate found this month) produces no event at all.
#
# On success, stamps two fully dedicated markers - z_aqd_debate_pending_
# pick_a on the pivot's location, z_aqd_debate_pending_pick_b on the
# partner's - rather than reusing the older shared z_aqd_fatwa_pending_
# pick for either (see that pair of static-modifier files' own headers
# for why: this feature always stamps two markers in the same tick, so
# sharing one with an unrelated pulse's own single pick would risk a
# same-tick collision that two fully dedicated keys make structurally
# impossible instead of merely unlikely). The event's own immediate can
# then unambiguously re-find each location via its own has_location_
# modifier check without any risk of either random_owned_location call
# resolving to the wrong one.
# ---------------------------------------------------------------------
aqd_debate_attempt = {
	aqd_debate_pick_pair = yes
	if = {
		limit = {
			exists = scope:debate_location_a
			exists = scope:debate_location_b
			exists = var:aqd_debate_seat_a_madhhab
			exists = var:aqd_debate_seat_b_madhhab
		}
		scope:debate_location_a = { add_location_modifier = { modifier = z_aqd_debate_pending_pick_a  months = 1 } }
		scope:debate_location_b = { add_location_modifier = { modifier = z_aqd_debate_pending_pick_b  months = 1 } }
		trigger_event_non_silently = { id = z_aqd_debate.1  days = 1 }
	}
	else = {
		remove_variable = aqd_debate_seat_a_madhhab
		remove_variable = aqd_debate_seat_b_madhhab
	}
}
